│  ┌─────────────────────────────────────────────────────────────────────────────────┐ │
│  │                      Intelligent Cache Management                              │ │
│  │                                                                                 │ │
│  │  Cache Structure:                                                               │ │
│  │  {                                                                              │ │
│  │    "_metadata": {                                                               │ │
│  │      "address": "ST2QKZ4FKHAH1NQKYKYAYZPY440FEPK7GZ1R5HBP2",                    │ │
│  │      "totalTransactions": 16413,                                                │ │
│  │      "fetchedAt": "2025-01-21T18:53:16.123Z",                                   │ │
│  │      "batches": 329                                                             │ │
│  │    },                                                                           │ │
│  │    "data": [ /* Array of transaction batches */ ]                              │ │
│  │  }                                                                              │ │
│  │                                                                                 │ │
│  │  ┌─────────────────────────────────────────────────────────────────────────────┐ │ │
│  │  │                    Cache Validation Process                                 │ │ │
│  │  │                                                                             │ │ │
│  │  │  Step 1: Address Comparison                                                │ │ │
│  │  │  • Check if requested address matches cached address                       │ │ │
│  │  │  • If different → Clear cache, fetch fresh data                            │ │ │
│  │  │                                                                             │ │ │
│  │  │  Step 2: Transaction Count Verification                                    │ │ │
│  │  │  • Fetch ONLY current transaction count (lightweight API call)             │ │ │
│  │  │  • Compare with cached count                                               │ │ │
│  │  │                                                                             │ │ │
│  │  │  Step 3: Smart Update Decision                                             │ │ │
│  │  │  • Counts match → Use cache (instant response, 0 API calls)                │ │ │
│  │  │  • Counts differ → Incremental update only                                 │ │ │
│  │  └─────────────────────────────────────────────────────────────────────────────┘ │ │
│  │                                                                                 │ │
│  │  ┌─────────────────────────────────────────────────────────────────────────────┐ │ │
│  │  │                    Incremental Update Strategy                              │ │ │
│  │  │                                                                             │ │ │
│  │  │  Example: Cached = 16,000 txs, Current = 16,010 txs                        │ │ │
│  │  │                                                                             │ │ │
│  │  │  Calculation: 16,010 - 16,000 = 10 new transactions                        │ │ │
│  │  │                                                                             │ │ │
│  │  │  Action:                                                                    │ │ │
│  │  │  1. Fetch only 10 new transactions: limit=10&offset=0                      │ │ │
│  │  │  2. Prepend new transactions to existing cache                             │ │ │
│  │  │  3. Update metadata (count, timestamp)                                     │ │ │
│  │  │  4. Preserve all historical data                                           │ │ │
│  │  │                                                                             │ │ │
│  │  │  Benefits:                                                                  │ │ │
│  │  │  • 99.9% reduction in API calls for returning users                        │ │ │
│  │  │  • Minimal bandwidth usage                                                 │ │ │
│  │  │  • Always up-to-date data                                                  │ │ │
│  │  │  • No redundant fetching                                                   │ │ │
│  │  └─────────────────────────────────────────────────────────────────────────────┘ │ │
│  │                                                                                 │ │
│  │  Cache Lifecycle:                                                               │ │
│  │  • Initial Analysis: Full fetch and cache creation                             │ │
│  │  • Same Address, No New TXs: Instant cache reuse (0 API calls)                │ │
│  │  • Same Address, New TXs: Incremental update only                              │ │
│  │  • Different Address: Cache cleared, new full fetch                            │ │
│  │  • Background Preloading: Automatic cache warming                              │ │

KEY ARCHITECTURAL DECISIONS
===========================

1. ADK-TS Framework Choice
   • Provides unified interface for multiple AI providers
   • Built-in MCP support eliminates custom tool integration
   • Automatic error handling and retry mechanisms
   • Production-ready agent orchestration

2. MCP Server Architecture
   • Separates blockchain logic from AI logic
   • Enables tool reusability across different agents
   • Follows official MCP specification for compatibility
   • Allows independent scaling of components

3. Smart Cache System
   • Dramatically reduces API calls (99.9% for returning users)
   • Incremental updates minimize bandwidth usage
   • Metadata-driven validation ensures data freshness
   • Background preloading improves perceived performance

4. Graph Protocol Design
   • AI has full autonomy in visualization creation
   • JSON-based protocol is language-agnostic
   • Supports 7 different graph types for flexibility
   • Rich tooltip data enables interactive exploration

5. Self-Correcting AI
   • debugAndFixCode tool enables autonomous error recovery
   • Up to 10 retry attempts with progressive fixes
   • Reduces user frustration from code execution errors
   • Improves overall system reliability

6. Testnet-First Approach
   • Safe development and testing environment
   • No risk to real assets during experimentation
   • Easy transition to mainnet (endpoint configuration only)
   • Allows for aggressive optimization without consequences
